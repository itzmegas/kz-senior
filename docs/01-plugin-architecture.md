# JumpStats plugin architecture and persistence

JumpStats 2.42 is a stateful AMX Mod X movement-statistics plugin: `fwdPreThink` performs classification, measurement, validation, ranking dispatch and presentation; `fwdPostThink` counts strafes and speed-gaining frames. Local persistence stores selected leaderboard summaries, not a complete movement history. SQL behavior crosses an unavailable include boundary. [reference/uq_jumpstats.sma:plugin_init:148-152; reference/uq_jumpstats.sma:fwdPreThink:1996-2202,4135-4672,5021-5683; reference/uq_jumpstats.sma:fwdPostThink:7799-7953; reference/uq_jumpstats.sma:save_tops:6850-6888; reference/uq_jumpstats.sma:include-directives:766]

## 2. Dataflow: engine samples to selected summaries

```text
Map/config/connection callbacks
   └─ cached settings, ladder bounds, identity, player-slot state
GoldSrc player-think callbacks
   ├─ PreThink: admission/reset → raw state reads → jump state machine
   │              └─ selected snapshots + peak/loss + bounded trajectory
   └─ PostThink: nominal turn/button segmentation → frame/sync counters
                         │ shared per-player arrays
Next qualifying PreThink: landing/failure finalization
   └─ distance candidates/helper → validity gates → aggregate rows
       ├─ selected tops or SQL calls (not an all-attempt archive)
       ├─ conditional anti-script incident log/actions
       └─ HUD/console/chat/visuals → deferred reset request
```

This diagram summarizes the existing call paths, not a proposed application architecture. Exact callback gates, line references and backend boundaries are in the table below.

| Stage | Inputs → state/output | Evidence |
|---|---|---|
| Initialize | Registered cvars → cached scalar settings; ladder entities → geometry arrays; local files → nested ranking tries, or scheduled SQL initialization. | [reference/uq_jumpstats.sma:plugin_init:434-465; reference/uq_jumpstats.sma:plugin_cfg:487-649,705-754] |
| Admit player/frame | Connected, non-bot, admin/team/alive checks → eligible PreThink processing. Spectators are enumerated for output delivery. | [reference/uq_jumpstats.sma:fwdPreThink:1996-2094,2204-2208] |
| Sample/classify | `pev_origin`, `pev_velocity`, buttons/oldbuttons, flags, movement type, gravity and maxspeed → ground/duck/bhop/ladder/drop state, takeoff origin/time and prestrafe. | [reference/uq_jumpstats.sma:fwdPreThink:2183-2202,3151-3220,3245-3328,3405-3434,3588-3625,3674-3807] |

The normal distance is the smaller of direct endpoint distance and an interpolated landing distance, each with `32.0` added except ladder-specific `laddist`. Failed-distance calculation delegates to the absent `GetFailedDistance`; this architecture document does not invent that algorithm. Overall sync is integer `good*100/(good+bad)` over the included strafe buckets, not an exported raw-frame sequence. [reference/uq_jumpstats.sma:fwdPreThink:4257-4331,4562-4583,4670-4672]

## 5. Lifecycle and reset semantics

1. **Load/configure:** register hooks/cvars, cache ladder geometry and map name; execute config before copying cvar values; initialize local or SQL branch. These cached values are not re-read by the shown per-frame enforcement loop. [reference/uq_jumpstats.sma:plugin_init:424-465; reference/uq_jumpstats.sma:plugin_cfg:475-649,705-754; reference/uq_jumpstats.sma:server_frame:1282-1314]
2. **Connect/join:** options derive from connection flags; per-slot movement/protection fields and stale tasks are reset. Join caches name/IP/Steam identity, optionally loads SQL player info and records admin status. Preferences are initialized from server defaults, not read from a visible local preference file. [reference/uq_jumpstats.sma:client_connect:8589-8734; reference/uq_jumpstats.sma:client_putinserver:1315-1335]
3. **Spawn/HUD:** spawn enables alive tracking and settings task; `ResetHUD` clears another subset of flags. PreThink also reconciles alive/dead/spectator state. [reference/uq_jumpstats.sma:FwdPlayerSpawn:8794-8804; reference/uq_jumpstats.sma:ResetHUD:8746-8793; reference/uq_jumpstats.sma:fwdPreThink:2006-2072]
4. **Attempt:** takeoff captures speed/origin/time and clears strafe counters/snapshots. `JumpReset(id,num)` only sets `g_reset`; `num` does not select different clearing logic. The actual reset occurs inside alive/team-eligible PreThink, clearing movement, beam and optional lost-frame state. [reference/uq_jumpstats.sma:fwdPreThink:2093-2181,3674-3799; reference/uq_jumpstats.sma:JumpReset:8125-8130]
5. **Invalidation/completion:** hook/teleport-like commands, unsafe contacts/settings, excess strafes, speed/weapon changes and validation failures request reset. Completed output requests reset too. A 0.4 s grounded interval (0.5 s for drop countjump) clears chain/protection state. [reference/uq_jumpstats.sma:client_command:1433-1475; reference/uq_jumpstats.sma:fwdTouch:6832-6844; reference/uq_jumpstats.sma:fwdPreThink:2209-2234,2269-2291,6193,6688-6729]
6. **Death/disconnect/unload:** death clears alive and selected tasks; disconnect additionally removes rendered entities, SQL membership and connection flags. `plugin_end` frees SQL handles plus membership trie or the two local top-level tries; there is no shown shutdown flush of attempt buffers. [reference/uq_jumpstats.sma:FwdPlayerDeath:8806-8833; reference/uq_jumpstats.sma:client_disconnect:8835-8885; reference/uq_jumpstats.sma:plugin_end:9347-9363]

Turning `/ljstats` off changes presentation flags (and remembers selected pre/warning flags for restoration); it is not a global sampling/persistence shutdown. The PreThink admission and ranking gates do not test `g_lj_stats`, whereas result HUD/console delivery does. [reference/uq_jumpstats.sma:cmdljStats:8185-8229; reference/uq_jumpstats.sma:fwdPreThink:1996-2094,5021-5033,5726-5729,5821-5824]

### 6.2 Local directory layout and loading

`get_datadir()` supplies the root: `Topljs`, `Topljs/block_tops`, and eight weapon-speed subdirectories under each (`Top_weapon_speed_<weapon_maxspeed(j)>`, `j=0..7`). Local mode creates `JData`/`JData_Block`, loads category/block files across `NTECHNUM`, then weapon variants across `NWPNTECHNUM` plus special `hj` block files. Exact type lists, counts and weapon-speed mapping depend on absent includes. [reference/uq_jumpstats.sma:plugin_cfg:705-754]

Each loaded row becomes a child trie referenced by a parent key: `<type>_<rank>_250`, `block_<type>_<rank>_250`, or the corresponding key ending in the weapon maxspeed. Fields include `name`, `authid`, numeric summary cells and, where applicable, `ddbh`, `block`, `jumpoff`, `pspeed`, `wpn_name`. The `authid` field name is historical: its value follows `rankby`, not necessarily Steam ID. [reference/uq_jumpstats.sma:read_tops:7011-7059; reference/uq_jumpstats.sma:read_tops_block:7060-7103; reference/uq_jumpstats.sma:read_tops_block_weapon:7104-7144; reference/uq_jumpstats.sma:read_tops_weapon:7145-7183; reference/uq_jumpstats.sma:checktops1:7193-7203]

### 6.3 File schemas

Rows are whitespace-separated, double-quoted tokens followed by newline, not JSON/CSV. Writers iterate `i < NTOP`; readers parse at most `NTOP` rows. Let `D`, `M`, `P` mean the scaled integer distance/maxspeed/prestrafe, `B` integer block, and `J` floating jump-off distance. [reference/uq_jumpstats.sma:save_tops:6859-6887; reference/uq_jumpstats.sma:read_tops:7018-7058; reference/uq_jumpstats.sma:checktops1:7187-7191; reference/uq_jumpstats.sma:save_tops_block:6916-6919]

| Relative path beneath `Topljs` | Token order | Evidence |
|---|---|---|
| `Top10_<type>.dat` | `name authid D M P strafes sync`; type indices `21..25` append `ddbh` | [reference/uq_jumpstats.sma:save_tops:6850-6888; reference/uq_jumpstats.sma:read_tops:7029-7049] |
| `block_tops/block20_<type>.dat` | `name authid B D J` | [reference/uq_jumpstats.sma:save_tops_block:6889-6920; reference/uq_jumpstats.sma:read_tops_block:7080-7089] |
| `Top_weapon_speed_<speed>/Top10_<type>.dat` | `name authid D M P strafes sync weapon_name` | [reference/uq_jumpstats.sma:plugin_cfg:734-740; reference/uq_jumpstats.sma:save_tops_weapon:6955-6991; reference/uq_jumpstats.sma:read_tops_weapon:7160-7173] |
| `block_tops/Top_weapon_speed_<speed>/block20_<type>.dat` | `name authid B D J weapon_name` | [reference/uq_jumpstats.sma:plugin_cfg:734-740; reference/uq_jumpstats.sma:save_tops_block_weapon:6921-6954; reference/uq_jumpstats.sma:read_tops_block_weapon:7124-7135] |
| `Top10_maptop.dat` | `name authid D M P strafes sync type_text` | [reference/uq_jumpstats.sma:save_maptop:6992-7009] |

`ddbh` carries `ducks[id]` for multi countjump variants, but `bhop_num[id]` for multi bhop. High jump shares the ordinary LJ distance-top dispatch, while block dispatch can use explicit `hj`; block loaders special-case `type_num==6` (base) or `9` (weapon) for that filename. [reference/uq_jumpstats.sma:fwdPreThink:5062-5066,5120-5151,5551-5555; reference/uq_jumpstats.sma:read_tops_block:7064-7068; reference/uq_jumpstats.sma:read_tops_block_weapon:7108-7112]

### 6.4 Quantization, identity and selection

- **Quantization:** `checktops1`, `checktops2`, `checktops_weapon` and `checkmap` calculate `floatround(value * 1000000)` for distance, maxspeed and prestrafe; block selectors scale distance only. This is six-decimal fixed-scale intent applied to already-floating measurements, not a guarantee of six-decimal measurement accuracy. Local jump-off remains a Float written with `%f`, unlike SQL's scaled jump-off payload. [reference/uq_jumpstats.sma:checktops1:7187-7191; reference/uq_jumpstats.sma:checktops2:7276-7280; reference/uq_jumpstats.sma:checktops_weapon:7648-7652; reference/uq_jumpstats.sma:checkmap:7733-7737; reference/uq_jumpstats.sma:checktops_block:7364-7366; reference/uq_jumpstats.sma:checktops_block_weapon:7503-7505; reference/uq_jumpstats.sma:save_tops_block:6916; reference/uq_jumpstats.sma:fwdPreThink:5648-5649]
- **Identity:** `rankby` selects cached name (`0`), IP without port (`1`, registered default), or Steam ID (`2`). Comparisons use `equali`, and retained strings use 33-cell name/identity buffers despite larger cached names. Name changes update the cached name; identity is therefore not inherently immutable or account-authenticated in local mode. [reference/uq_jumpstats.sma:plugin_init:249; reference/uq_jumpstats.sma:client_putinserver:1322-1324; reference/uq_jumpstats.sma:checktops1:7193-7205,7235,7251-7252; reference/uq_jumpstats.sma:client_infochanged:8737-8744]
- **Ordinary/weapon/map tops:** scan descending slots for a strictly greater scaled distance; find the same identity further down (or sentinel slot), shift intervening rows, insert and rewrite. Encountering the same identity before an improvement stops the scan. Equal distances do not replace a row and maxspeed/prestrafe/sync are not tie-breakers. Only `NTOP` rows are written. [reference/uq_jumpstats.sma:checktops1:7230-7271; reference/uq_jumpstats.sma:checktops2:7318-7360; reference/uq_jumpstats.sma:checktops_weapon:7691-7730; reference/uq_jumpstats.sma:checkmap:7751-7797; reference/uq_jumpstats.sma:save_tops:6861-6887]
- **Block tops:** lookup existing distance for this identity on the same block, accept when `bb >= tmp_block[i] && d > tmp_dist`, shift the old identity and insert; then sort same-block runs by descending distance when a block boundary is encountered. The final run is not explicitly sorted after the loop: do not claim a proven globally correct `(block, distance)` ordering. Weapon blocks use the same structure and also move weapon names. [reference/uq_jumpstats.sma:checktops_block:7402-7483,7498; reference/uq_jumpstats.sma:checktops_block_weapon:7541-7628,7643]
- **Eligibility precedes ranking:** only `!failed_jump && !not_save` enters persistence dispatch. Map top additionally requires baseline weapon maxspeed `250.0`, enabled main/map tops and excludes specified chain/invalid types. Categories branch on top/extras/weapon/block settings; block writes require nonzero jump-off and `block + jump-off < distance`. Displaying a failed result does not imply it was saved. [reference/uq_jumpstats.sma:fwdPreThink:4531-4540,5021-5051,5310-5365,5642-5683,5775-5816]

### 6.5 Durability and reset limitations

All five local writers delete an existing file and open the target in append-text mode, then rewrite bounded rows. There is no temporary-file/rename transaction or explicit successful-open check in these bodies. Readers open targets directly and parse tokens without a visible schema/version or field-count check. Treat crash consistency, missing-file handling and malformed/unescaped names as audit questions, not verified safeguards. [reference/uq_jumpstats.sma:save_tops:6852-6887; reference/uq_jumpstats.sma:save_tops_block:6891-6919; reference/uq_jumpstats.sma:save_tops_block_weapon:6923-6953; reference/uq_jumpstats.sma:save_tops_weapon:6957-6990; reference/uq_jumpstats.sma:save_maptop:6994-7008; reference/uq_jumpstats.sma:read_tops:7013-7058; reference/uq_jumpstats.sma:read_tops_block:7062-7102]

The map top is held in `map_*` arrays and rewritten to one fixed `Top10_maptop.dat` path, without map name in its schema. The shown initialization loads category/weapon/block files, not this map file; do not assume cross-restart map-top restoration or per-map file separation. [reference/uq_jumpstats.sma:global-declarations:52; reference/uq_jumpstats.sma:plugin_cfg:718-754; reference/uq_jumpstats.sma:save_maptop:6992-7009; reference/uq_jumpstats.sma:checkmap:7751-7782]

`reset_tops` clears only `JData` and `JData_Block` in local mode: it does not delete files or clear `map_*` arrays. SQL mode prints a failure message instead. A restart can reload uncleared local files; the command should not be documented as a durable full-data purge. Save/read routines create child tries and store their handles, but replacement/clear/unload paths shown here do not explicitly destroy each child handle; ownership cleanup deserves a runtime/API audit. [reference/uq_jumpstats.sma:reset_tops:8886-8905; reference/uq_jumpstats.sma:plugin_cfg:718-754; reference/uq_jumpstats.sma:save_tops:6863-6885; reference/uq_jumpstats.sma:read_tops:7022-7054; reference/uq_jumpstats.sma:plugin_end:9358-9362]

### 6.6 SQL: known interface, unknown implementation

The main file registers SQL enable/credentials and web settings; cached `kz_sql==1` schedules `stats_sql`/`save_info_sql`, creates `JumpPlayers`, loads player info on join and frees SQL handles on unload. Local top tries/loading use the separate `kz_sql==0` branch. Map-top dispatch occurs before the category backend branch and can still write its local file. A disconnect guard also mentions `kz_sql==2`, although the shown initializer only creates backend structures for `0` or `1`; mode `2` is not established as a working backend by this source. [reference/uq_jumpstats.sma:plugin_init:322-334; reference/uq_jumpstats.sma:plugin_cfg:490-492,712-754; reference/uq_jumpstats.sma:client_putinserver:1326-1329; reference/uq_jumpstats.sma:fwdPreThink:5021-5033; reference/uq_jumpstats.sma:client_disconnect:8837-8843; reference/uq_jumpstats.sma:plugin_end:9347-9362]

| Call | Ordered payload cells | Evidence |
|---|---|---|
| `PlayerSaveData_to_SQL(id, cData)` | `[distance×10^6 rounded, maxspeed×10^6 rounded, prestrafe×10^6 rounded, strafes, sync, bhop_count-or-ducks, type_number, weapon_maxspeed, weapon_id]` | [reference/uq_jumpstats.sma:fwdPreThink:5664-5682] |

### 6.7 Script incident log and generated configuration

`logs_path` is built from `amxx_logs` plus `\uq_jumpstats.txt`. `Log_script` appends separators, timestamp (`%m/%d/%y %H:%M:%S`), username/auth/IP, script/punishment text, type/weapon, distance/maxspeed/prestrafe (`%.03f`), strafe count, sync, total/flagged frames and bounded formatted strafe rows. This is a conditional incident log with personal identifiers, not a log of every jump. [reference/uq_jumpstats.sma:plugin_init:462-465; reference/uq_jumpstats.sma:Log_script:1212-1247; reference/uq_jumpstats.sma:fwdPreThink:5969-6002]

`kz_make_cvarexec` writes executable config text, including SQL host/user/password/database and plugin settings, using `fopen(...,"wt")`. This is configuration persistence, not jump telemetry; credentials can appear as plaintext in that file. [reference/uq_jumpstats.sma:kz_make_cvarexec:782-790,904-917; reference/uq_jumpstats.sma:plugin_cfg:659-662]

## Key Learnings:

1. The central contract is mutable player-slot state shared by PreThink/PostThink, not an append-only attempt/event model. Reset is deferred and full history is not retained. [reference/uq_jumpstats.sma:fwdPreThink:2093-2181; reference/uq_jumpstats.sma:fwdPostThink:7799-7953; reference/uq_jumpstats.sma:JumpReset:8125-8130]
2. Local tops are identity-selected, scaled-integer summary files with bounded row counts; the reset command does not erase durable files. [reference/uq_jumpstats.sma:checktops1:7185-7272; reference/uq_jumpstats.sma:save_tops:6850-6888; reference/uq_jumpstats.sma:reset_tops:8886-8905]
3. SQL schemas and structured demo telemetry cannot be reconstructed from SQL call sites or the demo-info HUD heuristic. They remain explicit evidence gaps. [reference/uq_jumpstats.sma:include-directives:766; reference/uq_jumpstats.sma:fwdPreThink:5642-5683; reference/uq_jumpstats.sma:client_command:1437-1449]

**Not checked:** compilation, runtime behavior, external dependencies/assets or SQL implementation. **Risk:** executing the plugin can mutate physics/client settings, overwrite files and trigger anti-script actions. [reference/uq_jumpstats.sma:include-directives:12-22,766; reference/uq_jumpstats.sma:plugin_cfg:682-754; reference/uq_jumpstats.sma:tskFps:1274-1281; reference/uq_jumpstats.sma:save_tops:6852-6887; reference/uq_jumpstats.sma:fwdPreThink:5969-6002]
